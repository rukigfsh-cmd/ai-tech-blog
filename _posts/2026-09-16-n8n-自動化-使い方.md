「毎朝同じサイトを見て、気になる情報をチャットに貼る」「フォームの回答をスプレッドシートにまとめる」——こうした繰り返し作業を、画面上でブロックをつなぐだけで自動化できるのが **n8n（エヌエイトエヌ）** です。

この記事では、2026年11月時点の公開情報をもとに、n8n の始め方を説明します。料金や画面は変わることがあるので、契約や本番利用の前に[n8n 公式サイト](https://n8n.io/)で最新情報を確認してください。

## 結論：まずはクラウドの無料試用か、手元のDockerで試す

| 始め方 | 向いている人 | 費用の目安 |
|---|---|---|
| **n8n Cloud** | サーバーの管理をしたくない人、すぐ試したい人 | 有料プラン（月額）。試用期間あり |
| **セルフホスト（Community Edition）** | PCやサーバーを自分で管理できる人、費用を抑えたい人 | ソフトは無料。サーバー代と管理の手間は自分持ち |

- 「とりあえず触ってみたい」なら、手元のPCに Docker で入れるのが一番お金がかかりません。
- 「24時間動かしたい」「外部からのWebhookを受けたい」なら、クラウド版か、常時動くサーバーへのセルフホストが必要です。

## n8nとは

n8n は、400以上のサービスと連携できるワークフロー自動化ツールです。「ノード」と呼ばれる部品（トリガー、HTTPリクエスト、Gmail、Slack、Googleスプレッドシートなど）を線でつなぐと、上から順に処理が実行されます。必要ならノードの中で JavaScript や Python のコードも書けます。

似たサービスに Zapier や Make がありますが、n8n は**自分のサーバーで動かせる（セルフホストできる）**のが大きな違いです。データを外部のサービスに預けたくない場合や、実行回数が多い場合に向いています。

ライセンスは「フェアコード」と呼ばれる独自のもので、社内や個人の自動化に使うのは自由ですが、n8n そのものを他人向けのサービスとして提供するような使い方には制限があります。商用で使う場合は、公式のライセンス説明を確認してください。出典：[n8n Docker イメージの README（GitHub）](https://github.com/n8n-io/n8n/blob/master/docker/images/n8n/README.md)

## クラウド版とセルフホストの違い

### n8n Cloud（公式のクラウド版）

- アカウントを作るだけで使えます。サーバーの準備、更新、バックアップは n8n 側が行います。
- 料金はプランごとに「月あたりのワークフロー実行回数」で決まります。2026年の各種まとめ記事では、Starter が月2,500回で月額24ユーロ前後、Pro が月10,000回で月額60ユーロ前後と紹介されています（年払いだと割安。**公式ページで要確認**）。出典：[n8n Pricing in 2026（Jetadmin）](https://www.jetadmin.io/blog/n8n-pricing/)
- 「実行回数」はワークフローが1回動くごとに1回と数えるので、ノードの数が多くても1回です。5分おきに動かすと、それだけで月8,000回以上になる点に注意してください。

### セルフホスト（Community Edition）

- ソフトウェア自体は無料で、実行回数の制限もありません。
- そのかわり、サーバー代（VPS なら月数百円〜）、アップデート、バックアップ、セキュリティ対策は自分で行います。
- 一部の機能（SSO、高度な権限管理など）は有料のエンタープライズ向けです。

## Dockerでn8nを動かす（公式の手順）

ここでは、PCに [Docker Desktop](https://www.docker.com/products/docker-desktop/) が入っている前提で説明します。以下のコマンドは n8n 公式の Docker イメージの README に書かれているものです（この記事の執筆環境では Docker を実行していないため、手順の動作は未検証）。

```bash
docker volume create n8n_data

docker run -it --rm \
 --name n8n \
 -p 5678:5678 \
 -v n8n_data:/home/node/.n8n \
 docker.n8n.io/n8nio/n8n
```

起動したら、ブラウザで `http://localhost:5678` を開きます。最初にオーナーアカウント（メールアドレスとパスワード）を作る画面が出ます。

### このコマンドの意味

- `docker volume create n8n_data`：ワークフローや認証情報を保存する場所（ボリューム）を作ります。
- `-p 5678:5678`：PCの5678番ポートで n8n の画面を開けるようにします。5678番がほかで使われているときは `-p 5680:5678` のように左側の数字を変えます。
- `-v n8n_data:/home/node/.n8n`：コンテナを消してもデータが残るようにします。

**重要**：`/home/node/.n8n` には、保存したパスワードやAPIキーを暗号化するための**暗号化キー**も入っています。このボリュームを消すと、保存済みの認証情報が使えなくなります。バックアップするときは、このボリュームごと保存してください。

### タイムゾーンを日本時間にする

決まった時刻に動かす「Schedule Trigger」ノードは、`GENERIC_TIMEZONE` という環境変数のタイムゾーンで動きます。日本時間で動かしたい場合は、`docker run` に次の2行を足します。

```bash
 -e GENERIC_TIMEZONE="Asia/Tokyo" \
 -e TZ="Asia/Tokyo" \
```

### 常時動かすなら Docker Compose

上のコマンドは、ターミナルを閉じると止まる「お試し」向けです。サーバーで常時動かす場合、公式ドキュメントでは Docker Compose を使う方法が推奨されています。HTTPS 化（リバースプロキシ）も合わせて設定してください。インターネットに公開する n8n には、必ず強いパスワードを設定しましょう。

## 最初のワークフロー例：ニュースを毎朝チャットに送る

ここでは「毎朝8時に、指定したサイトのRSSから新着記事を取得して、Discord に送る」例を考えます。画面の細かい表記はバージョンで変わることがありますが、流れは次のとおりです。

1. **新しいワークフローを作る**：画面左上などの「Create Workflow」から作成します。
2. **Schedule Trigger を追加**：「毎日」「8時」に設定します（タイムゾーンは上の設定どおり）。
3. **RSS Read ノードを追加**：読みたいサイトの RSS の URL を入れます。
4. **Filter ノードで絞り込む**：タイトルに特定のキーワードを含むものだけ残す、などの条件を付けます。
5. **Discord ノード（または HTTP Request ノード）で送信**：Discord のチャンネル設定で作った Webhook URL を使い、記事のタイトルとリンクを送ります。
6. **テスト実行**：「Execute Workflow」で1回動かし、各ノードの出力を確認します。
7. **有効化**：問題なければワークフローを Active（有効）にします。

各ノードの出力はJSON形式で画面に表示され、次のノードでは `{{ $json.title }}` のような式で前のノードの値を使えます。最初は「1つ追加するたびにテスト実行して、出力を見る」を繰り返すと、つまずきにくくなります。

## AIと組み合わせる

n8n には OpenAI や Anthropic などのAIサービスと連携するノードや、AIエージェントを組むためのノードがあります。たとえば「問い合わせメールをAIで分類して、担当者ごとにチャットへ振り分ける」といった使い方ができます。

ただし、AIの出力はまちがうことがあるので、**お客さんへの返信や支払いなど、取り消しにくい処理は人が確認してから**実行する設計にしましょう。AIの使い分けは「[Claude・ChatGPT・Geminiの違いと使い分け]({% post_url 2026-10-08-claude-ai-比較 %})」も参考にしてください。

## つまずきやすいポイント

- **Webhook が外から届かない**：手元のPCで動かしている n8n には、インターネットから直接アクセスできません。外部サービスからの Webhook を受けるには、公開サーバーで動かすか、トンネル（転送）サービスを使う必要があります。
- **時刻がずれる**：`GENERIC_TIMEZONE` を設定していないと、Schedule Trigger が想定と違う時刻に動きます。
- **認証情報が消えた**：ボリュームを消した、または別のボリュームで起動した可能性があります。
- **実行回数が多すぎる（クラウド版）**：短い間隔のトリガーは実行回数を大きく消費します。間隔を見直すか、処理をまとめましょう。
- **更新後に動かない**：アップデート前にバックアップを取り、リリースノートで破壊的な変更がないか確認してください。

## コードで自動化する方法との比較

プログラミングができるなら、Python のスクリプトと GitHub Actions のような仕組みでも同じことはできます。n8n は「画面で流れが見える」「認証まわりの部品が用意されている」点が便利で、コードは「細かい処理を自由に書ける」「無料枠で動かしやすい」点が便利です。コードでの自動化は「[GitHub Actionsで自動化]({% post_url 2026-10-08-github-actions-自動化 %})」も参考にしてください。

## まとめ

- n8n は、ノードをつなぐだけで色々なサービスを連携できる自動化ツール
- お試しなら Docker で無料、常時動かすならクラウド版かサーバーでのセルフホスト
- セルフホストでは `/home/node/.n8n`（暗号化キーを含む）のバックアップとタイムゾーン設定を忘れずに
- AIを組み込むときは、取り消しにくい処理の前に人の確認をはさむ
