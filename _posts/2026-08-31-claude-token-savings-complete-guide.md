## なぜトークンが問題になるのか

Claudeと長く作業を続けると、あるポイントから急に出力の質が落ちる——こんな経験はないだろうか。

原因はシンプルだ。**エージェントは長く動くほど劣化する。** ステップ50に達した時点で、モデルは49ステップ分の「もう必要ない文脈」を抱えながら、何がまだ真実かを判断し続けている。

Google研究者がこの問題に対し、驚くべき解決策を提示した。

| 手法 | トークン数 | スコア |
|------|-----------|--------|
| 会話履歴を要約して保持 | 600万 | 0.52 |
| state.jsonファイル1つで管理 | 12.2万 | **0.94** |

**1ファイルの変更だけで600万トークンを12.2万まで削減（98%減）、しかもスコアは0.52から0.94へ向上。**

## state.jsonパターン——98%削減の仕組み

### 考え方

従来のアプローチは「会話履歴を要約して渡す」だ。しかしこれには根本的な問題がある。要約が積み重なるほど、何が現在の真実かが不明確になる。

state.jsonパターンの考え方は正反対だ。

> **履歴を捨て、状態だけを持つ。**

- 会話が長くなっても、次のステップが必要な情報は常に一定量
- 「何があった」ではなく「今何が真実か」だけを記録する
- 毎ステップ後にファイルを上書きすることで常に最新状態を維持

```json
{
  "current_task": "ブログ記事の校正",
  "active_file": "_posts/2026-08-31-article.md",
  "status": "draft",
  "next_action": "SEOキーワードの最適化",
  "constraints": ["800字以内", "技術的正確性優先"]
}
```

100ステップ作業しても、このファイルのサイズは変わらない。会話が長くなっても、Claudeが読む文脈量は常に一定だ。

### なぜ要約より優れているのか

要約の問題は「選択と抽象化」にある。要約する際、「何が重要か」の判断が必要で、その判断自体が誤りうる。

state.jsonは選択しない。「現在の値」だけを保持する。数値、フラグ、ファイルパス——これらは要約できない事実だ。

## 4ステップで設定する

### ステップ1：プロジェクトの指示に追加する

Claudeのプロジェクト設定（Instructions）に以下を貼り付ける：

```
Keep a file called state.json. It holds only what the next step needs,
nothing about what already happened. Rewrite it after every step,
before doing anything else. Current values only, never a summary of
the conversation. Keep the same keys every time. At the start of a
session, read state.json instead of asking what we did last time.
```

**日本語版：**

```
state.jsonというファイルを維持してください。
次のステップに必要なものだけを保持し、過去に何があったかは書きません。
毎ステップ終了後、他の何かをする前に必ず更新してください。
現在の値のみを記録し、会話の要約は書きません。
毎回同じキー構成を維持してください。
セッション開始時は、何をしたか聞く代わりにstate.jsonを読んでください。
```

### ステップ2：新しいチャットを開く

既存のチャットには古い指示が読み込まれている。**必ず新規チャットを開くこと。**

### ステップ3：状態ファイルを初期化する

新しいチャットで以下を送信：

```
このプロジェクト用のstate.jsonを作ってください。
```

Claudeが実際の作業内容から適切なフィールドを選んでファイルを作成する。

### ステップ4：プロジェクト知識にアップロードする

作成したstate.jsonをProject knowledgeにアップロードする。これをしないと1つのチャットにしか存在せず、チャットを閉じると消える。

### 動作確認

新しいチャットを開いて「続けてください」と送信。前回の状態を質問せずに作業を再開できれば成功だ。

## Claude最大活用12ステップ

state.jsonパターンでトークンを削減したら、次はClaudeそのものを最大限に活用する設定を整える。一度設定すれば、毎回のセッションで自動的に機能する。

### 優先順位：Memory → Projects → Skills → Connectors → Automation

この順番が重要だ。後のステップは前のステップの設定を読む。特にAutomation（スケジュール設定）を先にやると、毎朝8時に間違ったアウトプットが届き続けることになる。

---

### 1. Memoryを読んで整える

**設定場所：** 左下 → Settings → Memory

まずここから始める。以下を有効にする：
- **Search and reference chats**（チャットを参照して記憶を更新）
- **Generate memory from chats**（チャットから記憶を自動生成）

Claudeがすでに記録している自分についての情報を確認する。4つのカテゴリがある：

| カテゴリ | 内容 |
|---------|------|
| Preferences | 好みのトーン・フォーマット・禁止事項 |
| Profile | 役割・技術スタック・担当領域 |
| Areas | よく扱うドメイン |
| People | よく出てくる人物名 |

間違いがあれば、テキストボックスで修正できる。「Xの作業はもうしていない」「Postgresを前提にしないで」のように普通の文章で書けばよい。

**今すぐ追加する価値がある2つ：**
1. 今月取り組んでいることと自分の役割
2. 絶対に出力してほしくない3つのこと

---

### 2. 繰り返す仕事をProjectにする

**設定場所：** サイドバー → Projects → New project

**これが最も重要なステップ。** 多くの人がここをスキップして「なぜ毎朝同じ説明をしているんだろう」と思い続ける。チャットは使い捨て。Projectは場所だ。

週2回以上やる仕事には全てProjectを作る。ニュースレター、クライアント対応、求職活動——それぞれ独自の指示・ファイル・記憶を持ち、Projectをまたいで情報が漏れない。

**Instructionsに書く4つのこと（この順番で）：**

1. このProjectが何か
2. 良いアウトプットとはどういうものか
3. 制約条件
4. 絶対にしてはいけないこと（最後の項目が最も効く）

```
これは開発者向け週刊ニュースレターのプロジェクトです。

良いアウトプット: 800字、1つのアイデア、具体例あり、まとめなし。
制約: 全ての主張は開けるソースを持つ。
絶対にしないこと: ダッシュ、絵文字、「昨今の急速な変化の中で」という表現、修辞疑問文。
```

Project knowledgeにスタイルガイドや過去の良い例をアップロードしておく。

**習慣にする：** Claudeが同じプロジェクトで2回同じ間違いをしたら、チャットで訂正するのではなく、Instructionsに1行追加する。

---

### 3. 繰り返す手順をSkillにする

**設定場所：** Settings → Skills

ProjectはContextを持つ。SkillはMethodを持つ。

いつも同じやり方でやること——リサーチの手順、レポートの構造、プルリクエストのレビュー——これはSkillだ。一度書けばどのチャットでも使え、タスクが合致したときにClaudeが自動的に読み込む。

**良いSkillを作る順番：**
1. 手作業で2回実行する
2. 良いアウトプットができたら
3. ClaudeにそのSkillを書かせる

想像で書いたSkillは自分のプロセスについての当て推量でしかない。

**Skillに含める5つの要素：**
- いつ使うか
- 何が必要か
- 手順
- アウトプットの形
- 絶対にしてはいけないこと

```
今やったことを「ソースチェック」というSkillとして保存してください。
手順、全ての主張には開けるリンクが必要というルール、
アウトプットのフォーマット、確認できなかったものは
削除するのではなくフラグを立てるというルールを含めて。
```

Anthropicが公式Skillを公開している：[github.com/anthropics/skills](https://github.com/anthropics/skills)

---

### 4. ツールを全部つなぐ（一度に）

**設定場所：** Settings → Connectors

各Connectorは、チャットに貼り付けることなくClaudeが読める情報源だ。**一度に全部つなぐ。** 必要になったときに1つずつつなぐより、複数がつながっているときに価値が出る。メールのスレッドから要点を取り出し、カレンダーで日程を確認し、結果をドキュメントに書く——これが一つの会話で完結する。

**つなぐ価値が高いもの：**

| ツール | できること |
|-------|-----------|
| Gmail / Microsoft 365 | スレッドを読む。M365は下書き・送信・カレンダー管理・OneDriveも |
| Google Calendar | スケジューリング・「あの打合せいつだっけ」への回答 |
| Google Drive | アップロードなしでドキュメントを読む |
| Notion | ノートを文脈として使える |
| Slack | 自分がいなかったスレッドから意思決定を取り出す |
| GitHub | Issue・PR・リポジトリの状態 |
| Linear / Jira | 今週自分に割り当てられているタスク |

**2つの確認：** 仕事用アカウントだけに権限を与える。つないだら小さな確認タスクを試す（「明日の会議は？」など）。正しく認証されていても範囲が間違っていると黙って失敗する。

---

### 5. 定型の繰り返し作業をスケジュールする

**設定場所：** サイドバー → Scheduled tasks → New Task → Create with Claude

スケジュールされたタスクは「指示 + 時刻」だ。クラウドで実行されるのでPCの電源が入っていなくても動く。

```
毎朝8時に、昨日のクライアントメールを読んで
約束したのにまだやっていないことをリストアップしてください。
何もなければそう言ってください。
```

**すぐ効果が出る3つのタスク：**
1. 朝の受信箱ダイジェスト
2. 金曜日の「追いかけているドキュメントやリポジトリで変更があったもの」まとめ
3. 週1回の「自分のノートで未完了のものを探す」パス

Projectの中で設定することで、すでに設定した指示とファイルを引き継げる。

**2つのルール：**
- 最初はread-only（報告するだけ、送信・投稿・削除しない）
- 最初の実行を必ず手動で確認する。5分で毎朝8時の間違いを防げる

---

### 6. ドキュメントの書き直しをやめる

Claudeが長い文章を書くと、チャットの横に開く。変更したい箇所をハイライトして、何を変えたいかを入力すると、そのセクションだけを書き直す。残りはそのままだ。

**常にやる作業に使う：** 「このセクションを半分に」「この段落を具体的に」「締めのまとめを削除」

Projectの中でやると修正がInstructionsに対して適用されるので、同じ間違いが次回から減る。

---

### 7. 答えではなくファイルを求める

Claudeはエクセルのワークブック・パワーポイントのデッキ・Wordドキュメント・PDFを直接作れる。チャットの答えはまだ仕事に変換しなければいけない。ファイルが仕事そのものだ。

**フォーマットを最初に指定し、形を具体的に：**

```
これをxlsxとして作ってください。
1行1費用、列は「サービス」「日付」「金額」「ソースファイル」。
月次合計を数式（貼り付け値ではなく）で出すサマリーシートも追加してください。
```

**1つのルール：** 最初のファイルはきちんと確認する。数式やページ数はチャットの答えでは見えないところに誤りが隠れる。

---

### 8. ExcelとPowerPointの中で作業する

Officeアドインをインストールすると、ファイルのやり取りなしに作業できる。Claudeはサイドパネルで開いているドキュメントを編集する——数式の作成、列のクリーニング、デッキのスタイル変更。両アドインは同じ会話を共有するので、スプレッドシートで計算した数値がそのままスライド作成の文脈になる。

**注意：** 実際にファイルの内容を編集するので、重要なファイルはコピーを保持しておく。

---

### 9. ブラウザを渡す

**Chrome拡張機能：** APIを持たないサービスの多くをカバーする。あなたの既存ログインセッションを使うので、内部ポータル・アナリティクスダッシュボード・外部サービスの管理画面にアクセスできる。

**初日に設定する価値がある3つ：**
1. ワークフローを一度記録して繰り返させる
2. ブラウザタスクをスケジュール実行
3. よく使うプロンプトをスラッシュコマンドにする

**2つのルール（ここが最も重要）：**
- 最初の1週間はread-onlyの作業だけ。間違いが無料なうちにミスを学ぶ
- 送信・購入・投稿・削除は必ず自分の承認を必須にする。あなたのアカウントで動いている

---

### 10. 他に方法がないときはPCを使わせる

**Cowork（Pro・Max）、研究プレビュー**

Claudeがファイルを開き、クリックし、画面に表示されているもので作業する。統合もセットアップもAPIも不要。

**最後の手段として使う。** Connectorの方が速く、ボタンが動いても壊れない。デスクトップソフトウェアや、他の方法がない内部システム向け——レガシーツール、自動化されていないエクスポート、Webバージョンのないアプリ。

遅く、監視が必要なので、明確な終了条件のある限定的な仕事を与える。

---

### 11. 説明文ではなくチャートを求める

Claudeはチャート・図・インタラクティブなビジュアライゼーションをインラインで表示できる。「見せて」と言えばものが出てくる。

**2つの習慣：**
1. プロットする前にデータを確認する。CSVをアップロードして「何が問題か」を先に聞く。重複・欠損・ありえない値をきれいにしてからプロットする
2. 同じメッセッドスレッドで繰り返す。軸を変え、セグメントで分け、別の切り口を試す

プロセスのフロー図なら一文でリクエストできて、書こうとしていた3段落より伝わる。

---

### 12. 設定の順番が全て

```
Memory と Projects → Skills → Connectors → Automation
```

Automationから始めた人は、毎朝8時に間違ったアウトプットを受け取り続けることになる。

**この設定にかかる時間：** 1晩。

**毎日取り戻せる時間：** 自分のことをゼロから説明するのにかかっていた20分、プラス、手作業では割に合わなかった作業。

新機能のロールアウトには波がある。今アカウントにない機能は、消えているのではなく順番待ちだ。

## 設定の優先順位

### 今すぐ絶対にやること（30分）

| # | 設定 | 効果 |
|---|------|------|
| 1 | Projectを1つ作る（最も使う仕事用） | 毎朝の説明20分を削除 |
| 2 | state.jsonパターンを設定 | トークン98%削減・精度向上 |
| 3 | Memoryを確認・修正 | セッション横断で文脈が継続 |

### 今週やること（2時間）

| # | 設定 | 効果 |
|---|------|------|
| 4 | 全Connectorを一度につなぐ | ツール間連携が機能し始める |

### 慣れてからやること

コンピュータ使用・Excel/PowerPointアドイン・Chrome拡張機能——これらは基盤が整ってから。基盤なしで自動化すると、間違った作業が毎日自動で届く。

## まとめ

トークン節約の本質は「情報の鮮度」だ。

何百ステップ前に決まったことを会話履歴の中に埋もれさせるのではなく、「今この瞬間に真実なこと」だけを1ファイルに保持する。600万トークンが12万になり、スコアが0.52から0.94になったのはそのためだ。

さらにその上に、Memory・Projects・Skills・Connectors・Automationを正しい順番で積み上げると、Claudeは毎回「初対面の相手」ではなく「あなたのことを知っているパートナー」として機能する。

設定にかかる時間は1晩。取り戻せる時間は毎日続く。
