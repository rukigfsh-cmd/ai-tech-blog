「RAG（検索拡張生成）を自分で作ってみたいけれど、ネットのサンプルコードが古くて動かない」という人向けに、**2026年11月時点で実際に動くコード**でRAGの基本を説明します。

この記事のコードは、Python 3 と chromadb 1.5.9 の環境で実行し、出力を確認しています（2026-11-19）。回答を生成する最後の部分（Claude API の呼び出し）だけは、APIキーを使っていないため**未検証**です。

## 結論：RAGは「検索してから、資料つきで質問する」しくみ

- RAGは、AIに質問する前に**手元の資料から関係する部分を検索**し、その部分を**質問と一緒にAIへ渡す**しくみです。
- AIが学習していない社内マニュアルや最新の情報についても、資料にもとづいた回答をさせやすくなります。
- 個人で試すなら、ベクトルデータベースの **Chroma** と、好きなLLMのAPIの組み合わせが手軽です。
- 「AIが資料にないことを言う」問題は減りますが、なくなりはしません。検索の精度と、プロンプトでの指示が大事です。

## RAGの流れ（4ステップ）

1. **分割（チャンキング）**：資料を数百文字ずつの「チャンク」に分ける
2. **ベクトル化と保存**：各チャンクを数値の列（埋め込みベクトル）に変換して、ベクトルデータベースに保存する
3. **検索**：質問も同じ方法でベクトルにし、意味の近いチャンクを上位から取り出す
4. **生成**：取り出したチャンクを「資料」としてプロンプトに入れ、LLMに回答させる

ファインチューニング（モデル自体の追加学習）と比べると、資料を差し替えるだけで知識を更新でき、費用も小さく済むのが利点です。違いは「[ファインチューニングの方法]({% post_url 2026-09-18-fine-tuning-方法 %})」も参考にしてください。

Chroma は、埋め込み関数を指定しないと、既定のモデル（all-MiniLM-L6-v2、ONNX版）を初回実行時に自動でダウンロードして使います（約80MB）。出典：[Chroma 公式ドキュメント（Embedding Functions）](https://docs.trychroma.com/docs/embeddings/embedding-functions)

## ステップ1・2：資料を分割して保存する

例として、ネットショップのよくある質問（FAQ）を3つ用意します。実際にはファイルから読み込んでください。

```python
# rag_index.py
import chromadb

# 1) 知識ベース（実際はファイルから読み込む）
docs = {
    "returns.md": "返品は商品到着から30日以内に受け付けます。開封済みのソフトウェアは返品できません。",
    "shipping.md": "通常配送は注文から2〜4営業日で届きます。離島は追加で2日ほどかかります。",
    "support.md": "サポート窓口は平日10時から18時まで、メールとチャットで対応しています。",
}

def chunk(text, size=200, overlap=40):
    """文字数で区切る単純なチャンク分割（重なりつき）"""
    out, start = [], 0
    while start < len(text):
        out.append(text[start:start + size])
        start += size - overlap
    return out

client = chromadb.PersistentClient(path="./rag_db")
col = client.get_or_create_collection("faq")

ids, texts, metas = [], [], []
for name, text in docs.items():
    for i, c in enumerate(chunk(text)):
        ids.append(f"{name}-{i}")
        texts.append(c)
        metas.append({"source": name})

col.upsert(ids=ids, documents=texts, metadatas=metas)
print("登録件数:", col.count())
```

実行結果：

```text
登録件数: 3
```

ポイント：

- `PersistentClient(path=...)` を使うと、データがフォルダに保存され、次回以降も使えます（`chromadb.Client()` はメモリ上だけで、終了すると消えます）。
- `upsert` は「同じIDがあれば上書き、なければ追加」です。何度実行しても重複しません。
- `metadatas` に出典ファイル名を入れておくと、回答に出典を示せます。

## ステップ3：質問に近いチャンクを検索する

```python
# rag_query.py
import chromadb

client = chromadb.PersistentClient(path="./rag_db")
col = client.get_collection("faq")

question = "開けたソフトは返品できますか？"
res = col.query(query_texts=[question], n_results=2)

for doc, meta, dist in zip(res["documents"][0], res["metadatas"][0], res["distances"][0]):
    print(f"[{meta['source']}] 距離={dist:.3f} {doc}")
```

実行結果：

```text
[returns.md] 距離=0.677 返品は商品到着から30日以内に受け付けます。開封済みのソフトウェアは返品できません。
[support.md] 距離=0.823 サポート窓口は平日10時から18時まで、メールとチャットで対応しています。
```

「開けたソフト」と「開封済みのソフトウェア」は言葉が違いますが、意味が近いので返品の資料が1位に来ました。これがキーワード検索との違いです。`distances` は小さいほど近いことを表します。

なお、検索は**いつも上位 n 件を返します**。資料に答えがない質問でも何かしら返ってくるので、距離が大きすぎる結果は捨てる、といった処理を入れると誤答を減らせます（しきい値は資料によって変わるので、実際の質問で試して決めます）。

## ステップ4：検索結果を資料にしてLLMに回答させる

検索結果をプロンプトに入れ、LLMに渡します。ここでは Anthropic の Python SDK を使う例です。

```python
# rag_answer.py
import chromadb
import anthropic

def retrieve(question, k=2):
    client = chromadb.PersistentClient(path="./rag_db")
    col = client.get_collection("faq")
    res = col.query(query_texts=[question], n_results=k)
    return list(zip(res["documents"][0], res["metadatas"][0]))

def build_prompt(question, hits):
    context = "\n\n".join(f"[出典: {m['source']}]\n{d}" for d, m in hits)
    return (
        "次の資料だけを根拠に、日本語で質問に答えてください。\n"
        "資料に答えがない場合は「資料には書かれていません」と答えてください。\n"
        "回答の最後に、使った出典名を書いてください。\n\n"
        f"<資料>\n{context}\n</資料>\n\n質問: {question}"
    )

def answer(question):
    prompt = build_prompt(question, retrieve(question))
    client = anthropic.Anthropic()  # 環境変数 ANTHROPIC_API_KEY を使う
    msg = client.messages.create(
        model="claude-opus-5-5",  # モデル名は公式ドキュメントで最新を確認
        max_tokens=2000,
        messages=[{"role": "user", "content": prompt}],
    )
    if msg.stop_reason == "refusal":
        return "回答できませんでした。"
    return "".join(b.text for b in msg.content if b.type == "text")

if __name__ == "__main__":
    q = "開けたソフトは返品できますか？"
    print(build_prompt(q, retrieve(q)))   # ここまではAPIキーなしで動く
    # print(answer(q))                    # APIキーを設定してから
```

`build_prompt` までは実行して、次のプロンプトができることを確認しました。

```text
次の資料だけを根拠に、日本語で質問に答えてください。
資料に答えがない場合は「資料には書かれていません」と答えてください。
回答の最後に、使った出典名を書いてください。

<資料>
[出典: returns.md]
返品は商品到着から30日以内に受け付けます。開封済みのソフトウェアは返品できません。

[出典: support.md]
サポート窓口は平日10時から18時まで、メールとチャットで対応しています。
</資料>

質問: 開けたソフトは返品できますか？
```

`answer()` の API 呼び出し部分は、この記事では実行していません（**未検証**）。使うときは APIキーを環境変数に設定し、モデル名と料金を[Anthropic の公式ドキュメント](https://docs.claude.com/)で確認してください。OpenAI など他社のAPIでも、「資料つきのプロンプトを渡す」という考え方は同じです。

APIを使わずに手元のPCだけで試したい場合は、[Ollama]({% post_url 2026-09-26-ollama-インストール-方法 %}) などのローカルLLMに同じプロンプトを渡す方法もあります。

## 精度を上げるためのポイント

### 1. 日本語に強い埋め込みモデルを選ぶ

Chroma の既定モデル（all-MiniLM-L6-v2）は主に英語で学習されたモデルです。上の例のような短い文なら日本語でも検索できましたが、資料が多くなると精度が落ちやすくなります。本格的に使うなら、多言語・日本語に対応した埋め込みモデル（例：multilingual-e5 系、各社の埋め込みAPI）を `embedding_function` に指定することを検討してください（この記事では未検証）。

**注意**：保存時と検索時で同じ埋め込みモデルを使う必要があります。途中でモデルを変えたら、データを入れ直してください。

### 2. チャンクの大きさと重なりを調整する

- 小さすぎる：文脈が切れて、答えの一部しか取れない
- 大きすぎる：関係ない内容が混ざり、検索の精度もプロンプトの効率も落ちる

日本語なら、まず300〜800文字程度、重なり1〜2割から試し、実際の質問で結果を見ながら調整するのが現実的です。見出しや段落の区切りで分けると、文の途中で切れにくくなります。

### 3. 出典を返し、「わからない」と言わせる

プロンプトで「資料にないときは、わからないと答える」「出典を書く」と指示すると、回答を確かめやすくなります。それでも誤った回答が出ることはあるので、重要な用途では人が確認する前提にしてください。

### 4. 小さく評価してから広げる

想定質問と正解を10〜20件用意し、「正しい資料が上位に来るか」「回答が正しいか」を確認しながら改善すると、勘に頼らずに調整できます。

## LangChain や LlamaIndex は使うべき？

LangChain や LlamaIndex を使うと、PDFの読み込みや分割、色々なベクトルDBへの切り替えなどを部品として使えます。ただし、ライブラリの更新が速く、古い記事のコード（`from langchain.vectorstores import Chroma` など）は現在のバージョンでは動かないことがあります。現在の LangChain では、Chroma との連携は `langchain-chroma` という別パッケージに分かれています。

まずはこの記事のように**ライブラリなしで仕組みを理解**し、必要になったら各ライブラリの公式ドキュメントのクイックスタートに沿って導入するのがおすすめです。

## よくある質問

### Q. ベクトルDBは何を使えばいい？

個人の試作なら、インストールが簡単な Chroma で十分です。データ量やアクセスが増えてきたら、マネージドサービス（Pinecone など）や、PostgreSQL の拡張機能 pgvector なども候補になります。

### Q. RAGを使えばハルシネーションはなくなる？

なくなりません。資料にもとづいて答えやすくなる一方で、検索で関係ない資料を拾ったり、資料を読み違えたりすることはあります。出典の表示と、人による確認を組み合わせてください。

### Q. PDFやWebページも使える？

使えます。PDFならテキストを取り出すライブラリ（pypdf など）で文字列にしてから、上の `docs` と同じように分割・保存します。他人のWebページを取り込む場合は、利用規約と著作権に注意してください。

## まとめ

- RAGは「分割 → ベクトル化して保存 → 検索 → 資料つきで生成」の4ステップ
- Chroma なら、数十行のコードで検索部分まで動かせる（この記事のコードは実行確認済み）
- 精度を上げるには、日本語に強い埋め込みモデル、チャンクの調整、出典と「わからない」の指示、小さな評価が効く

AIへの指示の書き方は「[プロンプトエンジニアリング入門]({% post_url 2026-09-27-プロンプトエンジニアリング-入門 %})」でも解説しています。
